Module 1

Data Science & Statistical Foundations

Core concepts & mathematical foundations

  • Linear regression predicts a continuous target, such as response latency. Fit the weights by minimizing mean squared error.
  • Logistic regression estimates the probability of a binary outcome, such as a timeout. Fit with binary cross-entropy and choose a decision threshold on validation data.

ŷ = wᵀx + b
MSE = mean[(y − ŷ)²]
p = 1 / (1 + e−(wᵀx + b))
BCE = −mean[y log(p) + (1 − y) log(1 − p)]

Engineering & API integration

  • Parse raw telemetry into a pandas DataFrame. Check types, units, duplicate events, and missing fields.
  • Use exploratory data analysis (EDA) to inspect distributions, outliers, and class imbalance.
  • Fit imputation and scaling on training data, apply the same transformations to validation data, and export the numeric features as NumPy arrays.

Bridge to RAG & multi-agent architecture

The same idea of learned scoring carries to TRINITY, where scores guide the next model and role selection.

By heartWhich regression fits latency? Which fits timeout risk?

Linear regression estimates continuous latency. Logistic regression estimates the probability of a timeout.

Module 2

Simulation & Uncertainty Modeling

Core concepts & mathematical foundations

  • Monte Carlo simulation estimates risk by repeatedly sampling uncertain inputs, such as response times or missing observations.
  • Track outcome variance across trials and report a confidence interval for the estimated failure rate, such as a Wilson interval for independent trials.

Estimated failure rate = failed trials / total trials

Engineering & API integration

  • Run seeded Python batches against a simulated workflow. Sample inputs and record the outcome of each trial.
  • Sweep timeout and retry settings. Compare failure rates across scenarios to identify where the workflow exceeds its error budget.

Bridge to RAG & multi-agent architecture

Use repeated trials to measure how agent loops respond to delay or missing evidence. TRINITY also evaluates candidate routing policies over repeated runs.

By heartWhat do you count after sampling many scenarios?

Count failures, divide by the number of trials, and report uncertainty around the estimate.

Module 3

API Integration & Model Endpoints

Core concepts & mathematical foundations

  • Follow the HTTP request–response lifecycle from method, headers, and JSON body to response status and payload.
  • Distinguish a synchronous response, incremental streaming chunks, and an asynchronous job that returns an ID for status polling.
  • Handle 429 rate limits with bounded backoff and honor Retry-After when supplied.

Engineering & API integration

  • Call a REST endpoint with a JSON payload or use a gRPC client with a typed service contract.
  • Configure supported LLM settings for temperature, top-p, and maximum output tokens.
  • Parse streaming chunks incrementally and poll only endpoints that expose asynchronous job status.

Bridge to RAG & multi-agent architecture

A coordinator can call separate model endpoints through adapters. Record each model’s settings and limits so you can compare routes under the same conditions.

By heartHow does streaming differ from polling?

Streaming delivers chunks on an open response. Polling sends separate requests to check job status.

Module 3 · Model internals

From Text to Next-Token Prediction

Tokenization & embeddings

A model-specific tokenizer maps text to vocabulary IDs. A tokenizer using byte-pair encoding can split a word into several tokens. Each ID maps to a learned vector, and the token count determines how much of the context window the input uses.

Transformer self-attention

Queries score keys to weight values. The causal mask M limits attention to current and earlier tokens.

softmax(QKT / √dk + M)V

The key dimension dk sets the scale. Transformer blocks combine multi-head attention, feed-forward layers, position information, residual connections, and normalization.

Logits & decoding

Softmax turns vocabulary logits into probabilities. Temperature reshapes that distribution. Top-k keeps the highest-scoring tokens, while top-p keeps the smallest highest-probability set that reaches a cumulative probability threshold.

Bridge to RAG & multi-agent architecture

Token budgets determine how much retrieved context fits in a request. Decoding settings affect variation in model-generated responses and tool arguments.

By heartWhy does the context window matter for RAG?

Retrieved passages consume input tokens, so the application has to select which evidence fits.

Module 4

The RAG & Vector Search Bridge

Core concepts & mathematical foundations

Embed queries and document chunks in the same high-dimensional vector space. Rank by dot product or cosine similarity, which normalizes for vector length. Use labeled queries to measure Precision@K.

cos(q, d) = (q · d) / (‖q‖ ‖d‖)
Precision@K = (relevant results in the top K) / K

Engineering & API integration

  • Index. Split documents along semantic boundaries, embed the chunks, and store vectors and source metadata in pgvector or Qdrant.
  • Retrieve. Embed the query, apply access filters, and rank matching chunks. Compare dense search with hybrid keyword search and reranking.
  • Generate. Serve a RAG endpoint that passes the top chunks to the model and returns an answer with source references.

Bridge to RAG & multi-agent architecture

Retrieval-augmented generation adds selected excerpts to the model’s context at inference time. Pass excerpts and source references together so downstream agents can verify the evidence.

By heartWhat does Precision@K count?

It is the fraction of the top K retrieved items judged relevant to the query.

Module 4 · Tool integration

Connect retrieval tools through MCP

Host, client, and server

The host coordinates the workflow, manages consent, and creates one MCP client per server. A server can expose resources for data, prompts for templates, and tools for callable operations.

In the 2026-07-28 revision, self-contained JSON-RPC 2.0 requests carry protocol version and client capabilities. Clients can call server/discover to check a server’s versions and capabilities.

Example · Read-only document search

  1. The client uses tools/list to discover the search tool and its input schema.
  2. The host checks permission and validates the query. The client sends tools/call, and the server enforces document access.
  3. The client validates the returned passages and source IDs. The host passes that evidence to the model.

MCP specification, 2026-07-28 · Architecture · Tools

By heartWho controls, connects, and serves?

The host manages consent and coordination. The client connects. The server exposes capabilities and enforces access.

Module 5

Agentic Workflows & Fundamental Routes

Core concepts & mathematical foundations

  • State transition graphs. Define the states and allowed transitions for each decision branch, including retries, review, and completion.
  • Deterministic routes. Apply fixed rules to observable state, such as routing insufficient evidence to review.
  • Model-driven routes. Let the model select from predefined transitions, such as retrieval or drafting.

Engineering & API integration

Define each tool’s inputs and outputs. Use JSON Schema to validate function-call arguments, check authorization before execution, and validate results before updating state.

Record the selected route and tool outcome. Bound the loop with step, retry, and time limits.

Bridge to RAG & multi-agent architecture

In the ReAct loop, the agent plans a step, acts by calling a tool such as retrieval, then observes the result and updates state before continuing or stopping.

Think → Act → Observe → repeat or finish

By heartWhat follows Think and Act in ReAct?

Observe. Read the tool result, update state, then decide whether to continue or stop.

Module 5 · Architecture

Multi-Agent Orchestration & Typed Contracts

  1. Orchestrator
  2. Researcher
  3. Validator
  4. Reviewer

Define roles and handoffs

The orchestrator assigns the task. The researcher returns findings with evidence. The validator checks the schema and source support. The reviewer approves release where policy requires it.

A typed JSON handoff can carry a task ID, status, findings, source IDs, and a structured error.

Handle failure at each boundary

  • Keep each agent’s working state scoped to its task.
  • Validate each handoff before forwarding it.
  • Retry transient failures within a budget and escalate when a handoff fails validation repeatedly.

Bridge to production observability

Carry a trace ID through each handoff. The core labs show what contract evidence to record, and ChatDev illustrates how artifacts move between stages.

By heartWhat does a receiver need to verify a handoff?

A task ID, a typed result, and source references. The receiver checks the contract and the evidence.

Module 5 · Research case study

ChatDev and the staged handoff

Design → coding → testing

A chat chain divides each phase into subtasks. An instructor agent and an assistant agent work through a subtask and pass the resulting artifact forward.

The assistant can ask for missing details before finalizing an artifact. The paper calls this communicative dehallucination.

Classroom example

Design a volunteer FAQ assistant. Write the requirements, implement retrieval, then test whether the answer cites the right policy. Ask the instructor which policy applies if the requirement is ambiguous.

The authors describe prototype-scale tasks and report added token and time costs from agent coordination.

Qian et al., ACL 2024, Fig. 2 and §§3.1–3.2, 6. ChatDev: Communicative Agents for Software Development (PDF)

By heartWhat does each phase hand to the next?

An artifact such as requirements, code, or test evidence. Ask for clarification when the requirement is vague.

Module 6

Production Observability & Governance

Core concepts & mathematical foundations

  • Drift. Compare input and output distributions with a baseline and investigate sustained shifts.
  • Latency and cost. Track median and p95 latency, input and output token counts, and effective cost per token.
  • Error propagation. Use a dependency tree to trace a failed call through downstream retries and handoffs.

Engineering & API integration

  • System logs. Write structured JSON to stdout with trace IDs, event names, and error codes.
  • Model performance logs. Record model version, latency, token consumption, and evaluation signals for drift tracking.
  • Observability and alerting. Instrument with OpenTelemetry, monitor metrics with Prometheus, and configure Grafana dashboards and alerts.

Bridge to RAG & multi-agent architecture

Use trace context to follow requests across MCP tools and agent handoffs. Route recurring failures to human review. MCP trace context conventions

Module 6 · Case study

Security, Guardrails & Evaluation Integrity

Control what each agent can do

  • Prompt injection. Treat retrieved text as untrusted data and enforce tool policies outside the model.
  • Least privilege. Scope tools by role and isolate execution where applicable.
  • Human approval. Pause for authorized review before high-impact actions. Log the decision against its trace ID.

BrowseComp evaluation

Anthropic found that leaked benchmark material could affect results. In its Claude Opus 4.6 runs on 1,266 problems, unintended solutions occurred on 0.24% of problems in the single-agent setup and 0.87% in the multi-agent setup.

Anthropic’s BrowseComp report

Review evidence across agent handoffs

Record which sources supported each answer and audit the retrieved evidence when benchmark integrity is in doubt. A higher score can reflect access to leaked answers.

By heartWhy can an answer be correct while the evaluation is invalid?

The answer may come from leaked benchmark material. Inspect the source and how it reached the agent.

Module 7 · TRINITY engineering

Build a coordinator that chooses the next turn

From transcript to routing decision

TRINITY feeds the request and prior turns to a compact Qwen3-0.6B model. A lightweight head reads the penultimate-token hidden state and scores the available models and roles separately.

The coordinator sends a role-specific prompt to the chosen model and adds its processed response to the transcript for the next turn.

Give each role a contract

  • Thinker proposes a plan or diagnoses a gap.
  • Worker produces a candidate solution or revision.
  • Verifier returns ACCEPT or REVISE, optionally with a diagnosis.

The run ends when the Verifier accepts or the turn budget runs out.

From course handoffs to adaptive delegation

Carry the lab’s role contracts and validated handoffs into a design where the coordinator chooses who takes the next turn.

Xu et al., Fig. 1–2 and §§2–3.2. TRINITY: An Evolved LLM Coordinator (PDF)

By heartWhat does the coordinator choose each turn?

A model and a role. The turn loop ends at Verifier acceptance or the turn limit.

Module 7 · TRINITY engineering

Learn a routing policy from task outcomes

Optimize for end-to-end success

With separable CMA-ES, sample variants of the routing parameters, run tasks end to end, score final task success, and use the better candidates to update the search distribution.

Training updates the routing head and selected singular-value scales in the compact coordinator. The external models keep their weights.

Transfer the lab’s testing method

Use the same fixtures to compare a fixed workflow and an adaptive router under the same limits. Record role and model choices, final test results, turns, and tokens.

ACCEPT is the stopping signal. The task’s test suite provides the separate measure of success.

Xu et al., §§2, 3.1, and 3.3. TRINITY paper (PDF)

By heartWhat makes one routing policy better?

More successful end-to-end runs on the same tasks under the same limits. Track turns and tokens alongside pass rates.

Module 7 · TRINITY engineering

Measure gains at a stated inference budget

LiveCodeBench V6 tested 175 newly released problems from January to April 2025. Pass@1 estimates the chance that one submitted solution passes the tests.

61.46% pass@1 · Bounded run

The paper’s default evaluation allowed up to five coordination turns and 4,096 generated tokens per model call.

86.2% pass@1 · Output cap removed

In a separate run, the authors removed the default output cap without retraining the coordinator. GPT-5 scored 83.8% in the same comparison, 2.4 percentage points below TRINITY.

On held-out tasks, TRINITY led the tested individual models on AIME, MT-Bench, and GPQA-D. It tied the best individual result on BigCodeBench (35.80).

Xu et al., §§4.1–4.5, Fig. 4 and Tables 1–2. TRINITY paper (PDF)

By heartWhich setup produced 86.2% pass@1?

The separate LiveCodeBench V6 run with the default output cap removed. GPT-5 scored 83.8% in that comparison.

Teaching & assessment

Applying the four AI literacy domains

Functional literacy

Trace a request from tokenization and retrieval through generation and a validated agent handoff.

Ethical literacy

Decide what telemetry can be logged, who can access documents, and when a tool action requires review.

Rhetorical literacy

Write role instructions for a specific audience and assess whether a generated answer supports its claims with evidence.

Pedagogical literacy

Use a worked example and a lab to assess whether learners can explain, test, and improve the workflow.

The lab outcomes adapt the four domains described by Stanford Teaching Commons. Understanding AI Literacy
